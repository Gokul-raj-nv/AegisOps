# INC-1842 — Payment Service HTTP 500 Surge

**Date:** 2024-11-20
**Duration:** 31 minutes
**Severity:** P1
**Service:** payment-service
**Status:** Resolved

## Summary

Payment service error rate rose to 32% with HTTP 500 responses. Investigation confirmed database connection pool exhaustion as the root cause — a repeat of INC-1521.

## Timeline

| Time | Event |
|---|---|
| 09:14 UTC | Error rate begins rising |
| 09:19 UTC | Alert fires: error rate >15% |
| 09:21 UTC | On-call paged |
| 09:28 UTC | DB pool utilization confirmed at 98% |
| 09:33 UTC | `DB_POOL_SIZE` increased 20→50, restart initiated |
| 09:41 UTC | Error rate drops below 1% |
| 09:45 UTC | All-clear |

## Root Cause

Despite INC-1521 actions, `DB_POOL_SIZE` was reset to 20 during a Helm chart rollback on 2024-11-18. The rollback reverted the environment variable to its default value.

## Evidence

- Log: `TimeoutError: QueuePool limit of size 20 overflow 0 reached` (347 occurrences in 5 minutes)
- Metric: `db_connection_pool_utilization{service="payment-service"}` = 98%
- Alert: `payment_error_rate` = 32%

## Resolution

- Increased `DB_POOL_SIZE` from 20 to 50 in Helm values (not just env override)
- Rolling restart of payment-service
