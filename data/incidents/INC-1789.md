# INC-1789 — Redis OOM Causing Notification Failures

**Date:** 2024-10-22
**Duration:** 2 hours 15 minutes
**Severity:** P2
**Service:** notification-service
**Status:** Resolved

## Summary

Redis ran out of memory due to uncapped queue growth during a notification processing outage. All email/SMS notifications were silently dropped for 2+ hours.

## Root Cause

A bug in notification-service caused the consumer to crash repeatedly. The Redis queue grew without bound, hitting the `maxmemory` limit. Redis then evicted messages using the `allkeys-lru` policy, silently dropping notifications.

## Resolution

- Fixed notification-service consumer bug
- Restarted Redis after clearing backlog
- Manually re-triggered notifications for affected orders

## Lessons Learned

- Set Redis `maxmemory-policy noeviction` for critical queues
- Add dead-letter queue for failed notifications
- Monitor queue depth, not just service health
