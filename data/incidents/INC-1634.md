# INC-1634 — Auth Service CPU Saturation

**Date:** 2024-09-30
**Duration:** 23 minutes
**Severity:** P2
**Service:** auth-service
**Status:** Resolved

## Summary

Auth service CPU reached 100% causing JWT validation latency to spike above 5 seconds, resulting in cascading 503 errors across order-service and payment-service.

## Root Cause

A change in the login flow doubled the number of bcrypt password validations per session. Combined with a 3x traffic spike from a marketing email, CPU was saturated.

## Resolution

- Scaled auth-service replicas from 2 to 4
- Reverted bcrypt change to previous implementation

## Lessons Learned

- CPU-intensive cryptographic operations must be profiled before shipping
- Services downstream of auth-service should cache JWT validation for short periods
